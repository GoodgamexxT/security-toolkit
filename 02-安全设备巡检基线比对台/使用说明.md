# 安全设备巡检基线比对台 · 使用说明

> 单文件网页工具，双击 `安全设备巡检基线比对台.html` 就能用。**离线可用、零依赖**，不需要 Python/Node，不上传任何数据。
> 独立工具，跟漏扫报告分析工具互不相干。

---

## 一、它解决什么

给十几二十台防火墙/WAF/IPS/审计设备做巡检，最耗时的不是看，而是**横向对比**：

- 逐台翻配置找「哪台没配 NTP」「哪台还开着 Telnet」「哪台 SNMP 还是 public」
- 每台语法还不一样：华为 `snmp-agent community read public`、思科 `snmp-server community public`、Linux `rocommunity public`
- 找完还得整理成矩阵，才能得出「这个问题影响了 8 台设备」

**它同时覆盖两种工作方式**：

| 方式 | 适合 | 怎么用 |
| --- | --- | --- |
| **自动比对** | 能从配置文本判断的项 | 粘贴配置 → 自动判定 22 项 → 横向矩阵 |
| **人工核查** | 判断不了的项（证书、备份策略、物理安全），或纯外部清单 | 点格子改判 + 填证据/问题，流程和清单式工具一致 |

自动判定先铺一遍，人工只处理「需人工核」和存疑项——这是它比纯清单工具省时间的核心。

**最关键的设计**：每条判定都能点开看**命中的原始配置行**。厂商语法差异大，正则一定会有误判，工程师必须能核实，而不是盲信颜色。

## 二、三步走

### 第 1 步 · 录入设备

每台设备 = 名称 + 类型 + 一段配置文本。三种录入方式：

| 方式 | 说明 |
| --- | --- |
| 添加设备 | 手动加卡片，粘配置 |
| 导入配置文件（可多选） | 一个文件 = 一台设备，文件名自动做设备名 |
| 粘贴合并文本 | 一个文件含多台设备时用，`==== FW-01 ====` 分隔（同一符号 4 个以上、两侧对称） |

设备类型可手选，导入时也会按关键词自动猜（waf / ips / 审计 / 防火墙）。

#### 配置从哪来（照着敲就行）

| 设备 | 取配置的方法 |
| --- | --- |
| 华为 USG / H3C | SSH 登录后 `display current-configuration`，全选复制；或 Web 上「系统 → 配置文件 → 导出」 |
| Cisco ASA / IOS | `show running-config`；或 `copy running-config tftp:` 存成文件 |
| 深信服 AF / AC / WAF | Web 控制台「系统 → 配置文件 → 导出配置」，导出的是 `.cfg` 或压缩包，解出来当文本用 |
| 天融信 / 绿盟 / 启明星辰 | 控制台「系统维护 → 配置备份」，多数导出明文脚本 |
| Linux 底座的审计/日志设备 | `sshd_config`、`snmpd.conf`、`rsyslog.conf`、`sysctl.conf` 一起 cat 出来粘进去 |
| 网上下载的样例配置 | 厂商文档里的「配置举例」、GitHub 上的 lab 配置、EVE-NG/GNS3 实验环境 `export` 出来的配置，都直接当文本用 |

**批量导出更省事**：在 Xshell / SecureCRT 里对所有设备会话同时发送 `display current-configuration`，
把回显分别存成 `FW-01.cfg`、`FW-02.cfg`… 然后「导入配置文件（可多选）」一次性全选进来。

#### 放进去之后：自动保存 + 配置包

- **自动保存**：设备名、类型、配置正文一旦改动就写入浏览器本地，刷新/关标签页不丢，下次打开自动恢复上次的巡检现场
- **导出配置包**：把所有设备配置 + 核查记录 + 规则打包成一个 JSON，用于备份、换机器、发给同事
- **导入配置包**：直接还原整套现场（会提示是否替换当前设备）

> 浏览器本地存储一般只有 5MB。几十台设备的完整配置可能超限，页面会提示
> 「自动保存失败…请用导出配置包备份」——这种情况就用配置包，别指望自动保存。
> 另外换浏览器/清缓存会丢本地存储，重要巡检结束请导出一次配置包或报告。

#### 三个注意点

1. **编码**：从设备导出的文件可能是 GBK。用记事本另存为 UTF-8 再导入，否则中文注释会变乱码（不影响规则匹配，但不美观）。
2. **配置里有敏感信息**：SNMP 团体字、`local-user ... password cipher` 密文、预共享密钥、公网 IP。
   工具本身不外传任何数据，但**导出的报告默认会把 IP/域名换成 `[[IP_001]]`**，配置原文请不要随手发出去。
3. **一个文件一台设备**。导出时文件名直接写设备名（`FW-HQ-01.cfg`），导入后设备名就有了，省得手动改。

### 第 2 步 · 检查规则

内置 **22 条**安全设备基线项，按类别分组，可逐条启停。

| 类别 | 检查项 |
| --- | --- |
| 账号与认证 | 默认/高危账号名、口令复杂度、登录失败锁定、三权分立、集中认证 AAA |
| 远程管理 | 禁用 Telnet、管理界面 HTTPS、禁用 HTTP 明文、管理访问源限制 |
| 日志与审计 | 日志外发 syslog、NTP 时间同步、命令/会话审计 |
| SNMP | 弱团体字（public/private）、SNMPv3 |
| 策略与防护 | any-any 放通、默认拒绝、WAF 防护模式、特征库版本 |
| 证书与许可 | License/授权到期、HTTPS 证书（需人工） |
| 高可用 / 其他 | 双机热备、FTP/TFTP 服务 |

**每条都带等保条款映射**（见第六节）。判定方式五种：命中=合规 / 命中=不合规 / 看捕获值 / 仅展示 / 人工。

### 第 3 步 · 比对结果

**统计卡片**：设备数、检查项、不合规合计、**待定**、零问题设备、**人工改判数**、平均合规率。

**三种视图**：

- **横向矩阵**：行=检查项，列=设备，格子带颜色和捕获值，人工改判过的格子右上角有 `*`
- **问题清单**：按设备列出不合规项 + 命中原文 + 条款 + 证据/问题 + 整改建议
- **按检查项聚合**：哪一项最多设备不合规

**点任意格子**打开详情面板：

```
自动判定：不合规    生效判定：通过  （人工改判）
当前值：public
命中的原始配置行（最多 8 处）
─── 可编辑 ───
人工改判：[跟随自动 / 通过 / 不通过 / 需关注 / 需人工核 / 待定 / 不适用]
证据 / 截图说明：[________]
问题描述：[________]
整改建议：……
```

改判和证据**即时生效并自动保存**，矩阵颜色和统计同步更新。原始自动判定始终保留（详情里能看到「原自动判定：不合规」），不会被覆盖。

## 三、人工核查层（对齐清单式工具）

| 能力 | 说明 |
| --- | --- |
| **人工改判** | 可把机器判定改成 通过/不通过/需关注/需人工核/**待定**/不适用；改判后格子带 `*`，详情里保留原始判定 |
| **证据留痕** | 每项可填证据说明（截图名、命令行输出摘要），进报告 |
| **问题描述** | 不通过项填问题，进报告的问题清单 |
| **必填校验** | 标记为「必须留证」的 5 项（证书、License、特征库版本、三权分立、WAF 防护模式），未填证据会被拦下 |
| **完整性校验** | 一次报出三类问题：① 待定项未给结论 ② 不通过但没写问题 ③ 需留证但没填证据 |
| **巡检人 / 周期** | 记入报告头 |
| **自动保存** | 设备配置、改判、证据、问题全部存 localStorage，关掉浏览器再打开能接着做 |

## 四、导出与导入

| 动作 | 产物 |
| --- | --- |
| 导出 CSV | 规则 × 设备的矩阵，Excel 直接开 |
| 导出巡检报告(HTML) | 概况 + 共性问题 + 逐设备问题清单 + 完整矩阵，可打印成 PDF |
| **导出 Markdown** | 含总览、设备概览、问题清单、**留证与人工记录**、说明段 |
| **导出 JSON** | 兼容清单式工具 schema（`templateName/operator/cycle/summary/results[]`），额外带 `device`、`standard`、`overridden` |
| **导入清单 JSON** | 直接吃「安全巡检剧本运行器」导出的 JSON，把它的检查项和已有结论/证据搬进来 |

**脱敏开关**默认开启：HTML/Markdown 导出前把 IP、域名替换成 `[[IP_001]]`，外发不用再手动处理。

### 导入清单 JSON 的行为（**按设备拆分**）

一份清单 = 一台设备 = 矩阵里一列。三种情况分别处理：

| JSON 里的情况 | 导入结果 |
| --- | --- |
| 带 `device` / `deviceName` / `host` 字段（多台混在一份） | **每台设备单独成列**，自动拆开 |
| 不带设备字段（就是「安全巡检剧本运行器」的原生格式） | 全部归到你填的设备名；没填就用「模板名（人工清单）」 |
| 设备名已存在 | 复用已有那一列，不重复建 |

具体规则：

1. **同一检查项在多台设备间复用同一条规则**，只累加「适用设备」范围——导入 5 台服务器不会让规则数翻 5 倍，矩阵还是 35 行 × 5 列
2. 某台设备独有的检查项，在别的设备上显示「不适用」，不会污染
3. 原 JSON 的 `status` / `evidence` / `issue` 按设备分别写入人工层，互不干扰
4. `operator` / `cycle` 若为空会自动带出
5. 兼容三种结构：`categories[]` 模板、`results[]` 结果、`items[]` 简化数组
6. 导入后自动跳到结果页

**典型用法**：每台服务器跑一遍那个工具、导出一次 JSON，依次导入并填上设备名（如 `srv-01`、`srv-02`），最后就是一张多服务器对比表。

> 脱敏开关默认开启：HTML/Markdown 导出前把 IP、域名替换成 `[[IP_001]]`，外发不用再手动处理。

### 矩阵过滤器

工具栏有「**隐藏不适用的行**」（默认开启）：一整行在所有设备上都是「不适用」时自动折叠。导入人工清单后，22 条内置项在没有配置文本的服务器列上会全灰，这个开关能把噪音挡掉；想看全量就取消勾选。

## 五、判定引擎的几个关键行为

都是踩过坑加的：

| 行为 | 说明 |
| --- | --- |
| **`no` / `undo` 开头不算命中** | `no telnet server enable` 不会被判成"开了 Telnet" |
| **注释行不算生效** | `# telnet server enable`、`! permit ip any any` 都忽略 |
| **空配置设备判「不适用」** | 没填内容的设备显示 `—`，不拉低合规率 |
| **类型不适用** | 规则可限定设备类型，不适用判 `—` |
| **人工改判优先级最高** | 但原始自动判定永久保留，可在详情里对照 |

## 六、等保条款映射

22 条规则各自映射到等保 2.0 三级的**子类**：

```
等保2.0 三级 · 8.1.2 安全通信网络 · 通信传输
等保2.0 三级 · 8.1.3 安全区域边界 · 访问控制
等保2.0 三级 · 8.1.4 安全计算环境 · 身份鉴别
等保2.0 三级 · 8.1.5 安全管理中心 · 集中管控
```

> **只引用到子类（8.1.x），不编造细项编号（8.1.4.1 这种）。** 具体条款号要按你项目的定级结果和被测评系统实际情况核对，工具不替你做这个判断。

## 七、自定义规则

第 2 步底部粘贴 JSON 数组：

```json
[
  {
    "id": "custom-af-ips",
    "name": "深信服 AF 开启 IPS 联动",
    "cat": "策略与防护",
    "level": "high",
    "pass": "found",
    "whenNoHit": "fail",
    "detect": ["ips[_ ]?link\\s*[:=]\\s*(1|true|enable)"],
    "exempt": [],
    "types": ["fw", "waf"],
    "standard": "等保2.0 三级 · 8.1.3 安全区域边界 · 入侵防范",
    "evidenceRequired": false,
    "advice": "在防护策略里开启 IPS 联动，否则只看流量不做阻断"
  }
]
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `pass` | `found`/`absent`/`capture`/`info`/`manual` | 判定方式 |
| `detect` | 正则数组 | **只写 JS 正则，不要加 `(?i)`**，大小写匹配时已忽略 |
| `exempt` | 正则数组 | 命中这些行的不算 |
| `badValues` | 值数组 | `capture` 模式下捕获值落入即判不合规 |
| `whenNoHit` | `pass`/`fail`/`warn`/`manual`/`info`/`na` | 一个都没匹配到时的结论 |
| `types` | `["fw","waf","ips","audit","other"]` | 限定适用设备类型 |
| `standard` | 字符串 | 等保/基线条款 |
| `evidenceRequired` | true | 标记为必须留证 |

## 八、已验证的项

- **规则引擎 44 项单测**：条款映射（并校验未编造细项编号）、人工改判合并、待定状态、原始判定保留、完整性校验三类问题、设备范围限定、清单 JSON 双向转换、Markdown 生成、原有判定回归
- **界面交互 42 项**（Chrome headless 真实 DOM，含自动保存/配置包往返）：载入示例 → 比对 → 点格子 → 改判 → 填证据 → 校验 → 导出构建 → 巡检人记录 → 自动保存 → 导入外部清单 JSON，**全程零未捕获异常**
- 累计此前：22 条规则正则全部可编译、`no`/`undo` 与注释行排除、多设备拆分、脱敏

开发中修掉的坑：

1. **PCRE 的 `(?i)` 在 JavaScript 里非法** —— 104 处内联标志导致大部分规则静默不匹配
2. **注释行被误判** —— `# 本设备时间同步缺失` 被中文关键字规则当成"已配置"
3. **需留证校验永远为 0** —— 需留证的项都是 manual/info 类，而校验只看了 pass/fail；现已把 manual/info 纳入
4. **多条规则共享同一个 devices 数组** —— 同一次导入里给每条规则传了同一个数组引用，往一条 push 设备会把所有条目一起改掉（表现为「某检查项莫名跑到别的设备上」）；已改为每条独立复制
5. **点「开始比对」会丢清单列数据** —— 原逻辑只算有配置文本的设备，导入的服务器列会被跳过；已改成对全部设备重算
6. **「载入示例」会静默清空已有设备** —— 现在有设备时会弹确认，不再误点即毁

## 九、已知限制（务必看）

1. **正则匹配是启发式的，不是配置解析器。** 特殊型号会漏判或误判，**结论必须抽样复核**。
2. **「需人工核」项无法自动判定**（证书有效期、物理安全、备份策略等），别当成已通过。
3. **策略有效性只能看配置，看不到命中计数。** 「策略长期未命中」「规则冗余」需要设备侧 `show` 计数器。
4. **弱口令无法验证**，只能看口令策略是否启用。
5. **合规率是自算的**，口径 = 合规 / (合规+不合规+需关注+待定)，不适用于对外宣称等保测评结论。
6. **等保条款只到子类级**，条款号需按项目定级结果核对。
7. **自动保存存在浏览器本地**，换机器/清缓存会丢；重要巡检结束请立即导出 JSON 或 HTML 归档。
8. 报告建议是**通用最佳实践**，具体到某台设备要结合业务判断。

## 十、下一步可以加的功能

- **批量 SSH 采集**：真正省时间，但需要本地 Python/Go 小服务（浏览器不能直连 SSH）
- **巡检台账**：多轮存档，看整改率趋势和「上轮问题改没改」
- **配置 diff**：选中两台设备做配置文本逐行对比
- **条款级映射**：允许自定义「规则 → 你项目的条款号」，覆盖内置子类映射
- **XLSX 导出**：现在只有 CSV/HTML/MD/JSON
